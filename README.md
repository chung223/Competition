# 競賽名次計算工具

給承辦人用的競賽成績計算小工具。設定出場序、評審委員與獎項名額後輸入成績，
系統以**名次法**自動計算名次、處理並列與決勝、分配獎項，並輸出可直接寄出的成績單。

純靜態網頁，**零外部相依**（不載入任何第三方字體或程式庫），可直接放上 GitHub Pages，
也可以把整個資料夾複製到隨身碟在無網路的比賽現場離線使用。

## 為什麼要用名次法

不同評審的給分基準常常差很多：有人打 95、92、90，有人打 72、68、65。
直接加總原始分數，會讓「給分大方的委員」對結果產生過大的影響。

本工具一律先把**每位委員的分數在該委員內部換算成名次**，再加總為「名次和」：

| 單位 | 委員甲 | → 名次 | 委員乙 | → 名次 | 名次和 |
|---|---|---|---|---|---|
| 甲隊 | 95 分 | 1 | 72 分 | 1 | **2** |
| 乙隊 | 92 分 | 2 | 68 分 | 2 | **4** |

名次和越低者名次越前。這樣無論委員給分寬鬆或嚴格，對結果的影響力都完全相同。

## 使用流程

1. **參賽單位** — 建立名單，**清單順序即為出場序**
   - 批次輸入：整份名單一行一個貼上，行首的 `1.`、`(2)`、`03、` 會自動移除
   - 自動產生編號：`第 1 隊`～`第 20 隊` 一次建立
   - 隨機抽籤：一鍵重新排定出場序
   - 建立後仍可拖曳、上下移動調整
2. **評審委員** — 輸入人數按「產生」，或直接貼上委員姓名。可指定一位**主審**
3. **獎項名額** — 自訂名稱與名額（例：一等獎 2 名、二等獎 3 名），或套用內建範本
4. **輸入成績** — 每位委員可各自用**分數**或**名次**填寫
5. **成績結果** — 切換顯示內容後輸出

## 成績輸入

兩種版面隨時切換：

- **逐位委員** — 一位委員一張表，對照紙本評分表輸入最不容易出錯。右側即時顯示換算後的名次
- **總表一次填** — 所有委員一次填完，右側即時顯示名次和與暫定名次

輸入操作：

| 操作 | 說明 |
|---|---|
| `↑` `↓` | 上下移動 |
| `Enter` / `Shift+Enter` | 下一列 / 上一列 |
| `←` `→` | 游標在字首／字尾時跳到左右欄 |
| 貼上 | 從 Excel 複製一整欄或一整塊，直接貼進任一格即整批填入 |
| 點選排序 | 名次模式專用：依偏好順序點選單位，自動填入 1、2、3… |

名次模式會即時檢查**重複名次**與**超出範圍**，有問題的格子會標紅。

## 決勝與並列

名次和相同時，依設定的順序逐條決勝（步驟 3 可調整順序或停用）：

1. **較優名次個數** — 獲得較優名次較多者列前（最常見的規則）
2. **原始總分** — 原始分數總和較高者列前
3. **主審名次** — 步驟 2 指定的主審所評名次較優者列前
4. **出場序** — 出場序較前者列前（用於強制排出唯一名次）

全部條件都相同時**並列同名次**，下一個名次跳號（1、1、3…）。
成績表會用註腳標明哪一名是靠哪一條決勝的。

並列跨越獎項名額時（例如並列第 1 但一等獎只有 1 名），可選：

- **順延遞減**（預設）— 並列者同獲一等獎，二等獎名額相應減少
- **增額** — 並列者同獲一等獎，後續獎項名額不受影響

其他可調規則：同一委員給分相同時的名次算法（平均名次 `2.5` 或競賽式 `1,2,2,4`）、
有委員漏評時的處理方式、未獲獎者的統一標示（例：佳作）。

## 輸出

| 形式 | 說明 |
|---|---|
| 成績單網頁 | 單一 HTML 檔，樣式全部內嵌，不需網路也不需本工具即可開啟，可直接當附件寄出 |
| 列印 / PDF | 專用列印樣式，附評審長／承辦人／主辦單位簽章欄 |
| CSV | Excel 可開，含計分方式與決勝順序附註 |
| JSON | 完整專案資料，可再匯入本工具繼續編輯 |
| 全螢幕公布模式 | 依獎項分組的大字名單，適合投影公布 |
| 複製成績表 | 以定位字元分隔，可直接貼進 Excel 或 Google 試算表 |

輸出前可切換顯示內容，這些設定會同步套用到列印與所有輸出：

- 顯示／隱藏各委員名次欄（只公布總成績時關閉）
- 委員以代號顯示（`委員甲`、`委員乙`…，避免公開個別委員的評分）
- 一併顯示原始分數
- 顯示名次和 / 平均名次

## 資料保存

所有資料只存在你這台裝置的瀏覽器 localStorage 中，**不會上傳到任何伺服器**，
編輯時自動存檔。換裝置或交接工作時，用「檔案 → 下載專案檔」帶走 JSON 再匯入即可。

## 本機執行

直接用瀏覽器開啟 `index.html` 就能使用（沒有使用 ES module，`file://` 亦可正常運作）。

或起一個本機伺服器：

```bash
npm start          # http://localhost:8080
```

執行名次計算核心的單元測試：

```bash
npm test
```

## 發布到 GitHub Pages

`.github/workflows/pages.yml` 會在推送時先跑單元測試，通過後才部署，
並且設定了 `enablement: true`，會自動替 repository 開啟 Pages。

如果部署步驟仍回報 `Get Pages site failed`，請到 repository 的
**Settings → Pages**，把 **Source** 手動設為 **GitHub Actions**，再重跑一次 workflow。

## 專案結構

```
index.html                  頁面骨架（五個步驟區塊）
assets/css/app.css          設計系統：色彩 token、深淺色主題、響應式、列印樣式
assets/js/rank.js           名次計算核心（純函式，可在 Node 下單獨測試）
assets/js/util.js           共用工具：DOM、對話框、拖曳排序、CSV、下載
assets/js/store.js          狀態管理、自動存檔、資料正規化
assets/js/steps-setup.js    步驟 1~3：參賽單位、評審委員、獎項與規則
assets/js/steps-score.js    步驟 4：成績輸入（鍵盤導覽、貼上、點選排序）
assets/js/steps-result.js   步驟 5：成績結果與顯示選項
assets/js/export.js         輸出：獨立 HTML 成績單、CSV、純文字
assets/js/app.js            應用外殼：步驟導覽、主題、檔案作業
tests/rank.test.js          計算核心單元測試
```

`rank.js` 不依賴 DOM，Node 與瀏覽器共用同一份程式碼，所以測試驗證的就是網頁上實際跑的邏輯。
